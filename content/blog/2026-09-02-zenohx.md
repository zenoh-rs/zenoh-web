{{< callout >}}
ZenohX is an open-source, high-performance desktop GUI client designed specifically for <strong>Eclipse Zenoh (1.10 Protocol)</strong>. Developed by the community, it provides real-time topology visualization, interactive pub/sub streaming, dynamic Protobuf schema codecs, and distributed query simulation.<br>
<br>
Check out the project on GitHub: <a href="https://github.com/khanhdew/ZenohX">github.com/khanhdew/ZenohX</a>.
{{< /callout >}}

Eclipse Zenoh has become a cornerstone protocol for robotics (ROS 2), edge computing, autonomous systems, and distributed IoT. While Zenoh's CLI utilities (`z_pub`, `z_sub`, `z_get`) and language SDKs provide rock-solid building blocks, exploring and debugging dynamic topologies often calls for a visual tool.

Enter **[ZenohX](https://github.com/khanhdew/ZenohX)**: a modern, cross-platform desktop application built with [Tauri v2](https://tauri.app), Rust, and React to deliver a native, responsive developer experience for Zenoh 1.10 networks.

![ZenohX Overview](../../img/2026-09-02-zenohx/overview.png)

## Motivation: My Journey from MQTT to Zenoh

Coming from an MQTT background, one of the first things I relied on was the availability of mature desktop GUIs like MQTTX and MQTT Explorer. When learning or debugging an MQTT broker, having a visual client to inspect wildcard subscriptions, monitor live message feeds, and verify Quality of Service (QoS) made understanding the protocol straightforward.

When I began exploring **Eclipse Zenoh**, I immediately saw its potential and believed it represented the future of data-in-motion:

- **Beyond Centralized Brokers**: True peer-to-peer, routed mesh, and client-router topologies with zero configuration overhead.
- **Unified Pub/Sub and Storage/Query (RPC)**: Rather than splitting streaming data and request/response queries into separate systems, Zenoh elegantly unifies both under key expressions.
- **Minimal Overhead & Transport Versatility**: Native support across TCP, UDP, QUIC, TLS, WebSockets, and Unix domain sockets with microsecond-level latency.

However, as I dove deeper into the ecosystem to learn and visualize my networks, I hit a major roadblock: **there was no official or functional desktop GUI client available for the Zenoh protocol**.

Learning a new distributed protocol shouldn't require writing boilerplate Python or Rust scripts just to check if a locator is reachable, verify multicast scouting, or decode a binary payload. I wanted an intuitive, visual tool to explore, test, and debug Zenoh networks in real time. Because that tool didn't exist yet, I decided to build **ZenohX**.

---

## Architecture: Lightweight, Low-Resource Desktop Client

Unlike heavy Electron-based desktop tools that bundle entire Chromium runtimes and consume hundreds of megabytes of memory, ZenohX is built with **Tauri v2** and **Rust** to keep resource usage minimal:

- **Tiny Executable Size**: By leveraging the operating system's native webview instead of shipping an entire browser engine, the standalone executable and installer stay exceptionally compact (under ~15 MB).
- **Minimal RAM Footprint**: Idle memory usage stays low (under ~30–50 MB), allowing ZenohX to run quietly in the background without competing for resources with your robots, simulators, or IDEs.
- **Native Rust Backend**: The networking layer communicates directly through official `zenoh` 1.10 Rust crates, providing instantaneous startup, direct socket management, and zero-copy data batching.
- **Embedded Local Storage**: Connection profiles, Protobuf schema files, and queryable presets are saved locally using SQLite with zero external database dependencies.

## Core Debugging Workflows

### 1. Interactive Network Topology & Mesh Visualizer

In multi-router or peer-to-peer mesh networks, understanding network connectivity can be difficult from terminal logs alone. ZenohX renders an interactive, physics-based graph of your active Zenoh session.

- **Node Discovery & Roles**: View active **Routers**, **Peers**, **Clients**, and automatically discovered nodes.
- **Live Traffic Animation**: Communication links visually pulse in real time whenever pub/sub samples or queries traverse the network.
- **Configurable Multicast Auto-Scout**: Background scouting continuously sweeps local LAN UDP multicast (`224.0.0.224:7446`) with customizable intervals (1s to 60s) or manual sweeps.
- **Node Inspector Drawer**: Inspect live runtime telemetry, examine bound locators (including dynamic ephemeral ports `:0`), and save discovered nodes to permanent profiles.

![Interactive Network Visualizer](../../img/2026-09-02-zenohx/network.png)

### 2. High-Throughput Pub / Sub Streaming & Traffic Generator

Testing data streams is as straightforward as entering a key expression:

- **Multi-Expression Subscriptions**: Subscribe to multiple key expressions simultaneously (e.g., `robot/*/telemetry`, `sensor/**`, `teleop/cmd_vel`) with wildcard matching and custom color tags.
- **Granular QoS Controls**: Configure reliability (`Express` / `Reliable`), congestion control (`Drop` / `Block`), priority, and subscriber locality (`Local` / `Remote` / `Any`).
- **Directional Indicators**: Color-coded borders distinguish incoming (`IN`) samples from outgoing (`OUT`) publications.
- **Continuous & Burst Stream Generator**: Simulate sensor streams with configurable intervals and parameterized JSON or raw payload templates.
- **Multi-Format Payload Viewers**: Inspect payloads as JSON, CBOR, Protobuf, plain text, or raw hexadecimal with tree hierarchy and wire-size calculation.

![Pub/Sub Workspace & Traffic Generator](../../img/2026-09-02-zenohx/pubsub.png)

---

### 3. Dynamic Protobuf Schema Registry & Automatic Wire Decoding

For robotics and embedded systems that transmit binary Protocol Buffers over Zenoh, inspecting raw byte buffers is impractical without automated decoding.

ZenohX includes an integrated Protobuf schema subsystem:

- **In-App Schema Manager**: Upload `.proto` files or write schema definitions directly inside an editor with live syntax checking and code formatting (`Ctrl+Shift+P` / `Cmd+Shift+P`).
- **Starter Presets**: Built-in starter schemas for standard robotics and IoT payloads (`sensor_msgs.proto`, `robot_control.proto`, `geometry_msgs.proto`).
- **Topic-to-Schema Mapping**: Bind Zenoh key expressions (e.g., `robot/sensors/**`) directly to target Protobuf message types.
- **Bidirectional JSON ↔ Protobuf Codec**: Write clean JSON in the publisher and let ZenohX encode it to binary Protobuf on the wire. Incoming binary wire samples are automatically decoded into formatted JSON and interactive tree views.
- **Sample Payload Scaffolding**: Generate valid mock JSON templates straight from compiled Protobuf message descriptors with one click.

![Protobuf Schema Registry & Codec](../../img/2026-09-02-zenohx/protobuf.png)

---

### 4. Distributed Query & JavaScript RPC Simulator

Zenoh's distributed query mechanism (`get()` and `Queryable`) enables unified RPC and storage querying. ZenohX turns query testing into an interactive sandbox:

- **Query Runner**: Send queries across routers and peers with latency tracking, timeout parameters, and a consolidated multi-reply timeline view.
- **Dynamic JavaScript RPC Handlers**: Define custom `Queryable` endpoints that execute sandboxed JavaScript logic to compute replies on the fly using `query.params`, `query.keyExpr`, and `query.payload`.
- **Interactive Script Sandbox**: Test and debug JavaScript RPC handlers locally before deploying them across the network.
- **Built-in Templates**: Ready-to-use starter templates for RPC Calculators, Dynamic Telemetry Sensors, Echo Inspectors, and Health Status endpoints.

![Distributed Query & RPC Simulator](../../img/2026-09-02-zenohx/query.png)

---

### 5. Multi-Transport Architecture & mTLS Security

ZenohX supports the full spectrum of Zenoh 1.10 transports and security configurations:

- **7 Supported Transports**: `tcp/`, `tls/`, `udp/`, `quic/`, `ws/` (WebSockets), `wss/` (Secure WebSockets), and `unixpipe/` (Unix Domain Sockets).
- **Role Presets**: One-click configuration presets for **Router**, **Peer**, and **Client** modes.
- **TLS & Mutual TLS (mTLS)**: Support for custom Root CA certificates, client certificates, and private keys, with strict TLS-only enforcement.
- **Live JSON5 Configuration Sync**: Real-time bidirectional JSON5 configuration inspector that synchronizes active session parameters, scouting policies, gossip discovery, and reconnect retries.

## Installation & Getting Started

ZenohX is distributed as lightweight, native standalone binaries for Linux, macOS, and Windows.

### 1. One-Line Install Script

**Linux & macOS:**
```bash
curl -fsSL https://raw.githubusercontent.com/khanhdew/ZenohX/main/scripts/install.sh | bash
```

**Windows (PowerShell):**
```powershell
irm https://raw.githubusercontent.com/khanhdew/ZenohX/main/scripts/install.ps1 | iex
```

---

### 2. Standalone Packages

Pre-built binaries are available from the [**GitHub Releases page**](https://github.com/khanhdew/ZenohX/releases/latest):

| Operating System | Package Format |
| :--- | :--- |
| **macOS** (Apple Silicon & Intel) | `.dmg` |
| **Windows** (x64) | `.msi` / `.exe` |
| **Ubuntu / Debian / Raspberry Pi OS** | `.deb` |
| **Fedora / RHEL / Rocky Linux** | `.rpm` |
| **Universal Linux** | `.AppImage` |

---

### 3. Building from Source

To build from source, ensure [Node.js](https://nodejs.org) (v18+) and [Rust](https://rustup.rs) (v1.75+) are installed:

```bash
# Clone the repository
git clone https://github.com/khanhdew/ZenohX.git
cd ZenohX

# Install dependencies
npm install

# Run in development mode (Vite + Tauri v2)
npm run tauri dev
```
